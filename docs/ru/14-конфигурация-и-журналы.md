# 14 — Конфигурация и журналы

**Русский** · [English](../14-configuration-and-logs.md)

Ядро работает на разумных значениях по умолчанию — отдельная настройка для запуска не нужна. Поведение тонко настраивается переменными окружения; журналы дают материал для разбора, когда что-то пошло не так.

## Переменные окружения

Все значения ниже — дефолты из текущего кода. Переменную задают в окружении демона или конкретного пира (через `launch.env`, см. [06 — Хранение](06-хранение.md)).

### Жизненный цикл

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `IAPEER_IDLE_SECS` | `3600` | Через сколько секунд простоя демон закрывает сессию агента (усыпление). |
| `IAPEER_BOOT_DEADLINE_SECS` | `240` | Сколько ждать загрузки сессии при подъёме, прежде чем считать запуск неудачным. |
| `IAPEER_READY_GATE_SECS` | `120` | Сколько ждать готовности агента к вводу после загрузки. |
| `IAPEER_CRASHLOOP_MAX` | `3` | Сколько смертей в окне допускается, прежде чем демон перестанет поднимать пир. |
| `IAPEER_CRASHLOOP_WINDOW_SECS` | `300` | Окно (секунды), на котором считаются смерти для защиты от цикла перезапусков. |
| `IAPEER_EPHEMERAL_QUIET_SECS` | `20` | Окно тишины, после которого свернётся эфемерный воркер, уже отправивший ответ. |
| `IAPEER_EPHEMERAL_UNARMED_IDLE_SECS` | `600` | Страховочный предел для эфемерного воркера, который молчит и не отправил ответ. |

Надзорный тик демона фиксирован — раз в минуту, не настраивается.

### Демон

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `IAPEER_PORT` | `8765` | TCP-порт роутера на `127.0.0.1`. |
| `IAPEER_DAEMON_SOCKET` | `~/.iapeer/state/iapeer/router.sock` | Путь локального сокета демона. |
| `IAPEER_BEARER_TOKEN` | — | Если задан, демон требует этот bearer-токен на входе; иначе проверка токена выключена. |

### Доставка сообщений

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `IAP_HOST_LIVENESS_GRACE_MS` | `4000` | Сколько ждать подтверждения, что сессия приняла сообщение, прежде чем считать её мёртвой. |
| `IAP_LIVENESS_GRACE_MS` | `3000` | Окно проверки живости занятой сессии (по сдвигу истории диалога). |
| `IAPEER_COMPOSER_QUEUE_TIMEOUT_MS` | `120000` | Сколько очередь композера ждёт, пока освободится поле ввода, прежде чем досылать принудительно. |
| `IAPEER_COMPOSER_QUEUE_POLL_MS` | `500` | Частота опроса поля ввода в очереди композера. |

### Пути и бинарники

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `IAPEER_ROOT` | `~/.iapeer` | Корень хранилища. Смена влечёт изоляцию сокетов в `<корень>/socks` (полезно для изолированных тестовых хостов). |
| `IAPEER_SOCK_DIR` | `/tmp` | Каталог сокетов host-wide. Переопределяет расположение host-wide. |
| `IAPEER_BIN_DIR` | `~/.local/bin` | Куда ставится бинарь `iapeer`. |
| `IAPEER_LAUNCHAGENTS_DIR` | `~/Library/LaunchAgents` | Каталог плистов launchd. |
| `IAPEER_CLAUDE_BIN` | `~/.local/bin/claude` | Путь к бинарю Claude. |
| `IAPEER_CODEX_BIN` | `codex` (из `PATH`) | Путь к бинарю Codex. |
| `NOTIFIER_RUNTIME_BIN` | `notifier-runtime` (из `PATH`) | Путь к лаунчеру notifier (для launchd с его минимальным `PATH`). |
| `TELEGRAM_RUNTIME_BIN` | `telegram-runtime` (из `PATH`) | Путь к лаунчеру Telegram. |
| `CODEX_HOME` | `~/.codex` | Переопределение каталога глобального конфига Codex. |

### Журналы

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `IAPEER_LIFECYCLE_LOG_MAX_BYTES` | `5 МиБ` | Размер `lifecycle.log`, при котором происходит ротация. |
| `IAPEER_LIFECYCLE_LOG_KEEP` | `5` | Сколько ротаций `lifecycle.log` хранить. |
| `IAPEER_DELIVERY_LOG_MAX_BYTES` | `5 МиБ` | Размер `delivery.log` для ротации. |
| `IAPEER_DELIVERY_LOG_KEEP` | `5` | Сколько ротаций `delivery.log` хранить. |
| `IAPEER_SUPERVISE_LOG_VERBOSE` | выкл. | Подробный лог надзорных тиков (по умолчанию пишутся только решения, не рутинные «ничего не делаю»). |
| `IAPEER_DAEMON_LOG` | выкл. | Расширенный лог демона. |

### Внутренние, dev и тестовые

`IAPEER_TEST_SANDBOX=1` включает защиту от записи в реальные пути: установка откажется писать в настоящий `~/.local/bin/iapeer` и потребует задать `IAPEER_BIN_DIR` на изолированный путь. Для разработки и автотестов, не для обычной работы.

Ещё несколько переменных система читает, но в обычной эксплуатации их не задают:

- `NOTIFIER_FALLBACK_TARGET` — запасной адресат для сигналов notifier; ядро резолвит его в плист пира при онбординге (без хардкода), вручную оператор его не выставляет.
- `IAP_TMUX_PASTE_SETTLE_MS`, `IAP_TMUX_SUBMIT_TIMEOUT_MS` — тайминги доставки во внутренней tmux dev-ветви; на проде используется pty-супервизор ([13 — Архитектура и контракт](13-архитектура-и-контракт.md)), вне разработки не нужны.
- `IAPEER_SHADOW_PATH` — `PATH` для shadow-fidelity прогона (внутренний инструмент разработки).

## Журналы и диагностика

Демон ведёт три долговременных журнала в `~/.iapeer/logs/iapeer/`:

- **`lifecycle.log`** — решения жизненного цикла: пробуждения, усыпления, перезапуски, итоги надзорных тиков. Первое место, куда смотреть, если пир ведёт себя не так.
- **`delivery.log`** — исход каждой доставки: кто, кому, в какой рантайм, результат, размеры, тема. Только метаданные — **тело сообщения не пишется**.
- **`exits.log`** — смерти сессий с посмертными данными: супервизор фиксирует причину (код выхода / сигнал) в момент смерти сессии.

### Посмертная диагностика

Причину смерти сессии (код выхода / сигнал) супервизор фиксирует в момент смерти — это то, что обычная проверка «жив ли процесс» не ловит. Отдельный сторож (canary) держит соединение с супервизором и при смерти сессии записывает в `exits.log` обстоятельства: память, swap, процессы по потреблению, системные отчёты диагностики. Это материал для ответа на вопрос «почему агент умер».

### Full Disk Access

Чтобы читать системные отчёты диагностики, бинарю `iapeer` нужен Full Disk Access (FDA) — разрешение macOS. `iapeer status` показывает, выдан ли FDA, и подсказывает, что делать, если нет. Без FDA пиры будут натыкаться на запросы TCC при доступе к защищённым папкам и контейнерам сторонних приложений.
