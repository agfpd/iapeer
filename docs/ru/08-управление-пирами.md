# 08 — Управление пирами

**Русский** · [English](../08-peer-management.md)

Повседневные операции с пирами. Полные сигнатуры команд с флагами — в [12 — CLI](12-cli-reference.md); здесь — когда и зачем применять каждую.

## Создание пира: create и init

Создать пир можно двумя командами, и разница между ними — в том, откуда берётся рабочая папка.

**`iapeer create <имя>`** создаёт пир из любого места. Команда сама выбирает папку (по умолчанию `~/.iapeer/peers/<имя>`, или укажите `--path`), разворачивает её и инициализирует. Это основной способ.

```bash
iapeer create assistant --runtime claude
iapeer create reviewer --runtime codex --description "Ревью кода и архитектуры"
iapeer create helper --path ~/projects/helper --runtime claude
```

**`iapeer init`** превращает в пир текущую (или указанную) папку. Это удобно, когда у пира уже есть своя папка проекта и хочется, чтобы `.iapeer/` появился прямо в ней.

```bash
cd ~/projects/myagent
iapeer init
```

Имя пира берётся из имени папки (нормализованный `basename` — `myagent`); отдельного флага для имени нет — чтобы пир назывался иначе, переименуйте папку. Рантайм определяется автоматически из установленных (Claude/Codex), при необходимости задаётся флагом `--runtime`.

По сути `create` — это «выбрать/создать папку, затем `init`». Обе команды выполняют одно и то же наполнение пира:

- пишут профиль `peer-profile.json`;
- заносят пир в реестр;
- настраивают подключение к демону по MCP (так агент получит `send_to_peer`);
- создают файл доктрины `IAPEER.md` для наполнения;
- если занят слот памяти — подключают общую память и проводят связанную с этим настройку рантайма.

Защита от затирания: если в целевой папке уже живёт другой пир (с другим именем в профиле), команда откажет, а не перезапишет.

Флаг `--no-bootstrap` создаёт пир, не запуская его службу (актуально для инфраструктурных пиров, которые иначе сразу поднимаются под launchd).

## Обзор пиров: list

```bash
iapeer list           # таблица
iapeer list --json    # машинно-читаемый формат
```

Каждая строка — пир, его рантаймы и состояние каждого: `●` живой, `○` спит, `✕` остановлен. Если запустить в интерактивном терминале, `list` открывает панель управления (стрелки для навигации, Enter — присоединиться, `/` — поиск, `q` — выход); в неинтерактивном режиме или с `--json` печатает таблицу для скриптов.

## Проверка целостности: verify

```bash
iapeer verify          # отчёт о расхождениях
iapeer verify --fix    # починить
```

`verify` проверяет две вещи: соответствие профилей стандарту и расхождения между реестром и локальными профилями. С `--fix` команда самовосстанавливает реестр из профилей (и попутно мигрирует профили со старого формата поля рантайма на актуальный). Это штатный способ привести реестр в порядок, если он рассинхронизировался.

## Остановка и запуск: stop, start

```bash
iapeer stop assistant          # остановить
iapeer start assistant         # снять остановку
iapeer stop --all              # остановить всех пиров
iapeer start --all             # снять остановку со всех
```

Поведение зависит от класса рантайма:

- **Агент claude/codex.** `stop` ставит стойкий стоп-флаг и закрывает сессию — демон не будит пир, пока не выполнят `start`. `start` снимает флаг: пир снова можно разбудить, но **сессия не запускается сразу** — демон поднимет её при первом сообщении.
- **Инфраструктурный пир.** `stop` снимает службу с launchd, `start` загружает обратно.

Можно адресовать конкретный рантайм: `iapeer stop assistant codex`.

## Безусловный перезапуск: new

```bash
iapeer new assistant
```

`new` — аварийный рычаг для зависшей или мёртвой сессии. В отличие от мягкого пути (когда живой агент сам читает команду и перезапускается), `new` действует механически, в обход агента: чисто сносит текущую сессию и поднимает свежую. Команда возвращает успех только тогда, когда свежая сессия действительно поднялась и готова. Это спасение для случая, когда агент завис настолько, что не читает ничего.

## Ленивый мягкий перезапуск: refresh

```bash
iapeer refresh assistant         # пометить пира на свежий старт при следующем пробуждении
iapeer refresh --all             # пометить все пиры
```

`refresh` — отложенный рычаг для случая «обновилась доктрина, хочу, чтобы команда её перечитала, но без рывка». Он **только ставит маркер**: не убивает живую сессию, не будит спящих, не делает немедленный перезапуск. Эффект наступает сам собой — на **следующем естественном пробуждении** пира (после штатного усыпления за простой, или на следующем сообщении спящему): вместо продолжения прежнего диалога поднимется свежая сессия, которая перечитает доктрину и фрагменты с диска.

Зачем отдельно от `new`: `new` — немедленный и жёсткий (рвёт текущую работу), а массовый `new --all` поднял бы разом всю команду. `refresh` — ленивый и мягкий: живую работу не трогает, всплеска пробуждений нет, свежесть приходит к каждому пиру в его обычный момент подъёма. Маркер перекрывает «продолжение» для **всех** типов пиров, в том числе людей-в-Telegram, которые иначе продолжают старую сессию до явного `/new`. Роутеры (notifier/telegram) и absent-рантаймы пропускаются — у них нет доктрины. Применять `refresh` — осознанный шаг оператора (например после релиза обновлённой доктрины), а не автоматический побочный эффект.

## Удаление: remove

```bash
iapeer remove assistant          # удалить запись из реестра
iapeer remove assistant --force  # удалить, даже если пир сейчас живой
```

`remove` удаляет запись пира из реестра. Важные свойства:

- **Папку пир не удаляет.** Данные пира (его `.iapeer/`, история, память) остаются на диске — `remove` чистит только запись в реестре. Если папка была одноразовой, удалите её сами.
- **Отказывает живому пиру.** Удалить запись работающего пира — значит оторвать его сессию от маршрутизации. Команда откажет, пока пир жив; обойти можно флагом `--force`, но честнее сначала остановить.
- **Идемпотентно.** Удаление несуществующего пира — не ошибка, а успешный ноль.

Типичное применение — подчистить «зомби»-записи, оставшиеся от завершившихся одноразовых пиров.

## Присоединение к сессии: attach

```bash
iapeer attach assistant
iapeer attach assistant codex    # конкретный рантайм
```

`attach` поднимает пир, если тот спит, продолжает его прежний диалог и открывает его сессию под супервизором прямо в вашем терминале — как обычную консоль. Отсоединиться — сочетанием `Ctrl-]` или просто закрыть терминал; сессия в любом случае продолжает работать в фоне, а `iapeer attach` снова подключит вас, когда понадобится.

## Граница: чужой launchd неприкосновенен

Команды `stop`, `start`, `new` **отказываются трогать пиров, которыми управляет чужой launchd-плист** (например, действующие пиры под отдельным менеджером жизненного цикла). Для таких пиров ядро — только читатель: вмешательство означало бы драку с launchd за управление процессом. Это сознательная защита, а не ограничение — она не даёт ядру случайно сломать то, чем владеет не оно.
