# 03 — Пиры, рантаймы, идентичность

**Русский** · [English](../03-peers-runtimes-identity.md)

Углублённая версия трёх базовых понятий из [обзора](01-обзор.md) — с уровнем детализации, нужным, чтобы создавать пиров, переключать их между рантаймами и читать профили.

## Пир

Пир — участник системы. У него есть рабочая папка, имя, набор рантаймов и природа.

### Имя (personality)

Имя — короткое логическое имя в нижнем регистре: `assistant`, `code-reviewer`, `timer`. Формат по шаблону `^[a-z][a-z0-9-]{0,31}$`: буква, дальше буквы, цифры, дефисы, до 32 символов.

Имя не хранится отдельной величиной — оно **выводится из имени рабочей папки**. Папка `~/.iapeer/peers/assistant` даёт имя `assistant`; не-латиница и прочие символы нормализуются к допустимому виду.

Отсюда жёсткое правило: **имя и рабочая папка связаны один к одному**. Занятое другим пиром имя — отказ, без молчаливого суффикса для развода коллизии. Имя — это адрес, и он обязан быть однозначным.

### Природа (intelligence)

Каждый пир несёт атрибут природы. Он едет вместе с сообщением, поэтому получатель знает, с кем говорит, не полагаясь на догадки.

| Значение | Кто это |
|---|---|
| `artificial` | AI-агент (Claude, Codex) |
| `natural` | человек (через Telegram и подобные каналы) |
| `absent` | программа без интеллекта (планировщик, наблюдатель, веб-хук) |

Природа по умолчанию выводится из рантайма: агентские рантаймы дают `artificial`, Telegram — `natural`, notifier — `absent`. При создании пира её можно задать явно.

Раньше использовались значения `human` и `scripted` — они и сейчас читаются (понимаются как `natural` и `absent` соответственно), но при записи система сохраняет то значение, что уже стоит в профиле, и не переписывает уже заведённых пиров.

## Рантайм

Рантайм — способ присутствия пира. Имя рантайма короче имени пира: формат `^[a-z][a-z0-9]{0,31}$`, без дефисов. Это важно для разбора идентичности (ниже).

### Два класса рантаймов

**claude, codex** — AI-агенты. Сессию не держат запущенной постоянно: демон поднимает агента на входящее сообщение и закрывает сессию после часа простоя. Этим рантаймом демон управляет полностью — поднимает и усыпляет.

**telegram, notifier** — рантаймы-роутеры, не AI. Telegram-мост принимает входящие в любой момент, notifier срабатывает по расписанию — поэтому работают постоянно под launchd с автоперезапуском. Такой рантайм демон **не трогает**: пробуждение и усыпление к нему неприменимы, его жизненным циклом распоряжается launchd. Это инфраструктурные рантаймы.

Деление — граница ответственности: демон отвечает за claude/codex, launchd — за инфраструктурные. Команды `stop`/`start`/`new` работают по-разному в зависимости от класса (см. [08 — Управление пирами](08-управление-пирами.md)).

### Несколько рантаймов у одного пира

Пир может объявлять несколько рантаймов. В профиле это два поля:

- **`runtimes`** — список всех рантаймов, на которых пир может присутствовать, например `["claude", "codex"]`.
- **`default_runtime`** — основной рантайм: куда по умолчанию маршрутизируются сообщения и какой рантайм поднимается первым.

Добавить пиру рантайм и сделать его основным — разные операции. Первая (`add-runtime`) расширяет возможности, не меняя маршрутизацию; вторая (`default-runtime`) переключает основной рантайм. Массовое переключение `default_runtime` по всем пирам — это и есть момент «пересадки» команды с одного агентского рантайма на другой. См. [09 — Рантаймы](09-рантаймы.md).

Список рантаймов пополняется и сам: при инициализации пира система сканирует его папку на признаки рантаймов (каталоги `.claude`, `.codex` и подпапки в `runtimes/`) и добавляет найденное в `runtimes`. Так список остаётся актуальным, даже когда рантайм появился у пира органически, а не был объявлен явно.

## Идентичность

Идентичность — адрес конкретного живого присутствия пира. Складывается из рантайма и имени через дефис:

```text
PEER_IDENTITY = PEER_RUNTIME + "-" + PEER_PERSONALITY
```

Пир `assistant` в Claude — это `claude-assistant`; он же в Codex — `codex-assistant`. Имя одно, идентичности две.

Разбор идентичности идёт **по первому дефису**: всё слева — рантайм, всё справа — имя. Поскольку в имени рантайма дефисов нет, а в имени пира они допустимы, разбор однозначен: `claude-code-reviewer` — это рантайм `claude` и пир `code-reviewer`.

### ABI идентичности

Три значения образуют ABI — набор переменных окружения, по которым любой компонент системы понимает, кто он:

| Переменная | Значение | Пример |
|---|---|---|
| `PEER_PERSONALITY` | имя пира | `assistant` |
| `PEER_RUNTIME` | рантайм текущей сессии | `claude` |
| `PEER_IDENTITY` | полный адрес | `claude-assistant` |

Когда демон поднимает сессию агента, он передаёт эти переменные в окружение. Агент по ним знает своё имя и от чьего лица отправляет сообщения. Рантайм текущей сессии определяется в таком порядке: из заголовка идентичности (`PEER_IDENTITY`), затем из профиля, затем из `PEER_RUNTIME`, и в последнюю очередь — автоопределением по признакам рантайма в окружении: Codex выставляет `CODEX_THREAD_ID`, Claude — `CLAUDECODE=1`. Если не сработал ни один источник, подъём отклоняется с требованием задать `PEER_RUNTIME` или завести профиль.

## Профиль и реестр

У идентичности два места хранения, и важно понимать, какое из них главное.

### Профиль пира — источник истины

`<папка-пира>/.iapeer/peer-profile.json` — это карточка пира, единственный источник истины о нём. Вот реальный профиль:

```json
{
  "personality": "assistant",
  "runtimes": ["codex", "claude"],
  "default_runtime": "claude",
  "runtime": "claude",
  "description": "Помощник общего профиля. Принимает задачи через IAP.",
  "intelligence": "artificial",
  "initial_prompt": "Новая сессия. Поздоровайся с владельцем.",
  "interfaces": {
    "telegram": { "bot": "assistant", "bot_username": "assistant_bot" }
  }
}
```

Поля профиля делятся на три класса по тому, кто ими владеет:

- **Ядро идентичности** — `personality`, `default_runtime`, `runtimes`, `description`, `intelligence`, `initial_prompt`. Этим владеет ядро и жизненный цикл. Поле `initial_prompt` — затравка первого хода свежей сессии. Поле `runtime` рядом с `default_runtime` — это синхронная копия для совместимости со старыми читателями; оба пишутся согласованно.
- **Приватная конфигурация плагина** — секции вроде `expansion` (шорткаты-алиасы), `notifier` (настройка пира-планировщика) и прочие, по одной на плагин. Читаются только из локального профиля, в реестр не попадают.
- **Публичный паспорт** — секция `interfaces` (например `interfaces.telegram.bot`). Это атрибуты маршрутизации, и они проецируются в реестр.

Описание `description` ограничено по длине (сейчас 450 символов) — оно само-документирующее, его видят другие пиры в реестре.

### Реестр — производная

`~/.iapeer/peers-profiles.json` — общий реестр всех пиров. Демон читает его, чтобы понять, кому доставлять сообщение и какие у пира рантаймы. Запись реестра содержит проекцию профиля: имя, основной рантайм, список рантаймов, описание, природа, рабочая папка, публичные интерфейсы.

Реестр — не источник истины, а **проекция** локальных профилей. Его можно пересобрать из профилей в любой момент (`iapeer verify --fix`). Если реестр и профиль разошлись, прав профиль — реестр чинится по нему.

Реестр пишется только через единственного писателя под файловой блокировкой — прямое редактирование `peers-profiles.json` запрещено на уровне ядра. Это исключает гонки, когда несколько процессов одновременно меняют состав пиров. Подробнее о раскладке и владении — [06 — Хранение](06-хранение.md).
