# 13 — Архитектура и контракт

**Русский** · [English](../13-architecture-and-contract.md)

Раздел для тех, кто разрабатывает под iapeer: рантайм-пакеты, capability-плагины, провайдеры памяти.

## Инварианты

На них держится поведение системы:

- **Один роутер.** В системе ровно один постоянно работающий демон. Все сообщения идут через него; второго маршрутизатора нет.
- **Идентичность на каждый запрос.** Демон не хранит сессию клиента — он определяет, кто к нему обратился, из заголовка `X-IAPeer-Identity` каждого MCP-запроса. Один слушатель обслуживает всех пиров.
- **Единственный писатель реестра.** `peers-profiles.json` пишется только через одного писателя под файловой блокировкой. Прямая запись файла запрещена на уровне ядра — это исключает гонки.
- **Живость определяется live-сессией пира.** Пир жив тогда и только тогда, когда у него есть живая сессия под супервизором. Это не отдельный флаг в состоянии, который можно рассинхронизировать, а наблюдаемый факт.
- **`доставлено` ⟺ легло в живую сессию.** Успех доставки означает, что сообщение принято живой сессией (демон дождался подтверждения). Не подтвердила — демон считает сессию мёртвой, а не лжёт об успехе.
- **Источник истины — локальный профиль.** Реестр — пересобираемая проекция профилей пиров. При расхождении прав профиль.
- **Бинарь установлен на хост.** Демон работает с установленного `~/.local/bin/iapeer`, а не из рабочего дерева исходников. Обновление — это замена бинаря и перезапуск демона на него.

## Рантайм-адаптеры на стороне ядра

Адаптер — слой ядра, который умеет запускать сессию рантайма. Все адаптеры реализуют единый интерфейс; различия рантаймов спрятаны за ним.

Ключевые свойства адаптера:

- **`kind`** — `tui` (интерактивная сессия, принимает ввод: claude, codex) или `router` (долгоживущий процесс без ввода: telegram, notifier).
- **`usesDoctrine`** — потребляет ли рантайм собранный системный промпт. Для TUI-агентов — да, для роутеров — нет (это не языковые модели).
- **`requiresIntelligence`** — гейт по природе пира. У `telegram` это `natural`: попытка завести Telegram-присутствие у не-человека отклоняется с явной ошибкой.
- **`buildArgv`** — как собрать команду запуска: для роутеров это `<рантайм>-runtime run` плюс дополнительные аргументы из `launch.env`.

Роутеры пропускают все TUI-фазы: у них нет загрузочных диалогов, маркеров готовности, подтверждения доставки и контрольных команд. Их живость держит launchd, а не пробуждение демоном.

Продакшен-механизм хостинга TUI-сессий — **pty-супервизор**: супервизор-демон владеет pty сессии и её pane-логом, через его сокет идёт доставка на ввод.

## Контракт рантайм-пакета

Рантайм-пакет (`*-runtime`) — npm-пакет, добавляющий инфраструктурный рантайм. Примеры: `@agfpd/notifier-runtime`, `@agfpd/telegram-runtime`.

### Манифест runtime.json

Пакет при self-install пишет манифест в `~/.iapeer/runtimes/<рантайм>/runtime.json`. Ядро его читает.

```json
{
  "runtime": "notifier",
  "version": "0.2.0",
  "selfConfig": { "command": "notifier-runtime", "args": ["self-config"] },
  "peers": [
    { "personality": "timer",   "intelligence": "absent", "description": "Планировщик по расписанию" },
    { "personality": "watcher", "intelligence": "absent", "description": "Наблюдатель за событиями" }
  ]
}
```

| Поле | Тип | Обязательность | Назначение |
|---|---|---|---|
| `runtime` | строка | обязательно | ID рантайма, совпадает с именем папки; шаблон `^[a-z][a-z0-9]{0,31}$` |
| `version` | строка | опционально | Версия пакета. Используется для гейта при `update-runtime`; без неё обновление просто переустанавливает |
| `selfConfig` | дескриптор | опционально | Хук персональной настройки, вызывается ядром на каждого пира при провижне |
| `peers` | массив | опционально | Объявленный набор пиров. Есть — режим declared-set; нет — operator-add |

Элемент `peers[]`: `personality` (обязательно), `intelligence`, `description`, `path` (явная папка), `runtimeBin` (путь лаунчера) — последние четыре опциональны.

**Дескриптор** (`selfConfig` и подобные) — это `{ "command": "...", "args": [...] }` или просто строка-команда.

### Два режима развёртывания

- **declared-set** — манифест содержит `peers[]`. `iapeer install-runtime <рантайм>` разворачивает весь набор сразу (notifier разворачивает `timer` и `watcher`).
- **operator-add** — `peers[]` пуст или отсутствует. Пиров заводит оператор по одному: `iapeer create <имя> --runtime <рантайм>` (так подключают людей в telegram).

### Что ядро вызывает у пакета

Контракт минимален — ядро обращается к пакету ровно тремя способами:

1. **`npx <пакет>`** — при установке. Пакет идемпотентно раскладывает свой бинарь на `PATH` и пишет `runtime.json`.
2. **`<рантайм>-runtime run`** — при запуске сессии (через launchd-плист или launch). В окружении — `PEER_PERSONALITY`, `PEER_RUNTIME`, `PEER_IDENTITY`.
3. **Хук `selfConfig`** — при провижне каждого пира. Вызывается в рабочей папке пира; в окружении — `IAPEER_PEER_PERSONALITY`, `IAPEER_PEER_CWD`, `IAPEER_PEER_RUNTIME`, `IAPEER_PEER_INTELLIGENCE`. Код возврата 0 — настроено (идемпотентно), иначе — ошибка (плист пишется, но не загружается).

Команды вроде `prepare`, `interface`, `bot`, `doctor` — это внутренние команды самого пакета для оператора, а не контракт с ядром: ядро их не вызывает.

### Установка и обновление

- **`install-runtime <рантайм>`** определяет npm-пакет (по встроенному реестру или флагу `--package`), ставит его через `npx`, затем разворачивает объявленный набор пиров.
- **`update-runtime <рантайм>`** сверяет версию манифеста с npm; при отставании переустанавливает, заново провизионирует и перезапускает пиров рантайма штатными `stop`/`start`.

## Стандарт capability-плагина

Capability-плагин добавляет пиру способность, не будучи рантаймом. Отличие чёткое: рантайм — способ присутствия пира, плагин — способность поверх рантайма.

### Манифест iapeer.json

Плагин может (но не обязан) положить в свой корень `iapeer.json`:

| Поле | Тип | Назначение |
|---|---|---|
| `setup` | дескриптор | Шаг установки плагина. Вызывается при `enable`, если объявлен и установка прошла |
| `requires` | — | Зависимости (рантаймы, другие плагины). Ядро их не разрешает — плагин проверяет их сам и отказывает, если зависимости нет |

Плагин без `iapeer.json` или без `setup` — это простой класс: ставится и включается, дополнительной инициализации нет.

### enable

`iapeer enable <плагин> [пир]` по шагам:

1. Находит пир (по имени или по текущей папке); отказывает, если у пира нет агентского рантайма.
2. На каждом агентском рантайме пира ставит плагин: для Claude — в область проекта внутри папки пира (`plugin install … --scope project`), для Codex — в общий конфиг хоста. Установка попутно включает плагин.
3. Если объявлен `setup` и установка удалась — вызывает его. В окружении: `IAPEER_PEER_PERSONALITY`, `IAPEER_PEER_CWD`; рабочая папка — корень плагина. Шаг best-effort: его сбой не откатывает уже сделанные установку и включение.

Идемпотентность: для Claude привязка идёт по реальному пути папки пира, поэтому повторный `enable` не задевает другие пиры и не дублирует установку.

### Критерии iapeer-совместимости

Плагин считается совместимым, если он:

1. полезен сам по себе;
2. объявляет, что предоставляет и что требует;
3. не владеет чужой ответственностью;
4. имеет идемпотентную подготовку;
5. имеет самодиагностику (`doctor`/`status`);
6. использует общий ABI идентичности (`PEER_*`), когда тот доступен;
7. не требует от пользователя вручную синхронизировать идентичность между плагинами;
8. одинаково понимает имя, рантайм и идентичность под Claude, Codex и будущими рантаймами.

## Контракт слота памяти

Память даёт провайдер, занимающий единственный на хост слот. Слот занят ровно одним провайдером или пуст.

### Манифест провайдера

Провайдер атомарно пишет `~/.iapeer/memory-provider.json`; ядро только читает. Удаляет файл — освобождает слот. Ядро слот никогда не пишет.

```json
{
  "provider": "iapeer-memory",
  "package": "@agfpd/iapeer-memory",
  "version": "0.2.7",
  "registeredAt": "2026-06-11T17:46:41.449Z",
  "heartbeat": "/Users/me/.iapeer/state/iapeer-memory/memoryd.heartbeat",
  "provision": {
    "command": "/Users/me/.local/bin/iapeer-memory",
    "args": ["provision-peer", "--cwd", "{cwd}", "--runtime", "{runtime}",
             "--personality", "{personality}", "--occasion", "{occasion}"]
  },
  "unprovision": {
    "command": "/Users/me/.local/bin/iapeer-memory",
    "args": ["unprovision-peer", "--cwd", "{cwd}", "--runtime", "{runtime}",
             "--occasion", "{occasion}"]
  }
}
```

| Поле | Тип | Обязательность | Назначение |
|---|---|---|---|
| `provider` | строка | обязательно | Имя провайдера |
| `package` | строка | обязательно | npm-пакет |
| `version` | строка | обязательно | Версия пакета |
| `registeredAt` | ISO-дата | обязательно | Когда занят слот |
| `heartbeat` | путь | опционально | Файл сердцебиения демона провайдера; `iapeer status` показывает его свежесть |
| `provision` | дескриптор | опционально | Команда настройки памяти пира при рождении |
| `unprovision` | дескриптор | опционально | Команда сворачивания при удалении пира |

`command` обязан быть абсолютным путём; `args` — массив строк. Невалидный блок ядро трактует как отсутствующий, пустой слот — как нормальное состояние.

### Команды provision/unprovision

В аргументах подставляются четыре плейсхолдера (подстановка пер-аргумент, на уровне подстроки):

| Плейсхолдер | Значение |
|---|---|
| `{cwd}` | рабочая папка пира |
| `{runtime}` | конкретный агентский рантайм (`claude` / `codex`) |
| `{personality}` | имя пира — обязан совпадать с `normalize(basename({cwd}))` (имя пира и папка соотносятся 1:1); несовпадение → `ensurePeerProfile` завершается ошибкой |
| `{occasion}` | момент вызова (см. ниже) |

**Моменты вызова, которые эмитит ядро:**

- **`birth`** — при рождении пира, по одной команде на каждый агентский рантайм. Идёт после предварительного доверия codex к папке, чтобы поверхности провайдера легли в уже доверенную папку.
- **`remove`** — при удалении пира, по команде на агентский рантайм. Идёт до очистки состояния пира — провайдер видит его в последнем согласованном виде.

**Окружение:** команда наследует всё окружение ядра; специальные `IAPEER_PEER_*` сюда ядро **не** добавляет — провайдер опирается на плейсхолдеры в аргументах. stdin игнорируется, stdout/stderr захватываются.

**Семантика выполнения:** код возврата 0 — успех; иначе — ошибка; превышение 120 секунд — таймаут; недоступный бинарь — отдельный исход. Всё best-effort: сбой команды не валит ни рождение, ни удаление пира, но громко логируется. Провайдер обязан быть идемпотентным — ядро может вызвать одну команду повторно.

### Рычаг родной памяти

Когда слот занят, держать параллельно родную память рантайма вредно. Ядро при рождении пира с занятым слотом отключает её:

- **Claude** — в `<папка>/.claude/settings.json` дописывает `"autoMemoryEnabled": false`;
- **Codex** — в `<папка>/.codex/config.toml` дописывает `[features] memories = false`.

Включить обратно — удалить ключ (восстановить умолчание рантайма). Вручную: `iapeer native-memory off|on`. Для Codex ядро при рождении заодно прописывает доверие к папке (`[projects."<реальный-путь>"] trust_level = "trusted"`), чтобы проектный конфиг читался с первой сессии; при удалении пира эта запись снимается.
